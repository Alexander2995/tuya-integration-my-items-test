# Результаты проверки — 22 октября 2026

- Среда проверена в Windows 11 x64: Temurin Java/Javac 17.0.20, Maven 3.9.16. WSL не использовался.
- Spring Boot 4.1.2; исходники компилируются для Java 17.
- Упаковка JAR: **BUILD SUCCESS**, **21 тест**, 0 ошибок, 0 пропусков. 13 исходных тестов и 8 проверок очереди прошли; после освобождения используемого Windows JAR упаковка завершена без повторного выполнения неизменённых тестов. Для кэша зависимостей при автоматической проверке использовался рабочий каталог вне исходников; на обычный способ запуска это не влияет.
- Успешный запуск через `mvn spring-boot:run` и отдельно собранного `target/tuya-local-demo-0.1.0.jar`.
- HTTP главной страницы: **200**. Локальный `/api/snapshot` возвращает состояние приложения без обращения к Tuya.
- Подтверждён слушающий адрес: **127.0.0.1:8080**.
- POST без локального заголовка и POST с посторонним Origin: **403**.
- Страница открыта в браузере; проверены русские тексты, состояние незаполненного секрета, выключенное автообновление, недоступность команд до подключения и отсутствие выдуманных показаний.

Автоматические проверки используют искусственный транспорт. Они проверяют официальный пример подписи, точный масштаб и единицы, отсутствие данных, выбор реле, Cloud v2 модель/время отчёта, обезличивание, кэш и обновление токенов, сохранение показаний при ошибке, тело/подпись команды, offline, неподтверждённую команду, конфигурацию, параллельные операции и защиту локального запроса.

Дополнительно проверены AES-GCM (расшифровка и отказ при изменённом теге/неверном режиме), `auth1`, частичные обновления без REST, дубликаты, старые события, фильтрация другого устройства, типизация строковых значений IoT Core по модели, отдельные времена свойств и порядок online/offline.

**Реальная очередь:** по уточнению пользователя клиент переключён на TEST, приложение перезапущено. Клиент успешно авторизован и подписан на тестовый канал европейского сервера, с включённой проверкой TLS и режимом AES-GCM. За 45 секунд наблюдения сообщений не поступило (received=0, applied=0, rejected=0); реальная доставка и расшифровка входящего сообщения ещё не подтверждены. Требуется проверить включение конкретной розетки в список тестовых устройств и правила отправки отчётов либо дождаться следующего отчёта устройства. Состояние очереди и счётчики показаны на странице.

**SSE:** поток `/api/events` отвечает HTTP 200; начальный JSON и последующий JSON обновления разобраны успешно. После отдельного ручного REST-чтения новый снимок автоматически доставлен по тому же открытому SSE-соединению. Браузер показывает подключение страницы. Это проверка локальной передачи, а не доказательство доставки сообщения из Tuya.

**Реальное чтение Tuya проверено после локального заполнения секрета:** авторизация, модель, информация устройства и свойства получены успешно через CLOUD_V2. Облако подключено, розетка online. Определено доступное для записи реле `switch_1`, его состояние — включено. Получены мощность 12,1 Вт (scale=1), напряжение 228,1 В (scale=1), ток 0,276 А (исходно mA, scale=0). Значения приведены как пример фактически полученного снимка, они изменяются со временем. Для `add_ele` единица не распознана; энергия оставлена без нормализованного значения. Реальная розетка в ходе проверки не переключалась; принятие и подтверждение команды проверены только искусственным транспортом.

При смене ключей заполните `TUYA_CLIENT_SECRET` в `tuya.local.properties`, сохраните, перезапустите приложение и нажмите «Обновить». Секрет не нужно отправлять в чат. Содержимое локального файла не публикуется и не включается в архив.
